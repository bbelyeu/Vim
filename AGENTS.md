# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this repo is

This is Brad Belyeu's personal **Vim configuration**, published as `bbelyeu/Vim` on
GitHub. It is cloned to `~/.vim`, and [`vimrc`](vimrc) is aliased/symlinked to
`~/.vimrc`. Everything here is real, in-daily-use config — treat changes with the
same care you would production code, because a broken `vimrc` breaks the user's
editor everywhere.

There is **no build step and no application code**. The "product" is the Vim setup
itself.

## How to verify changes (test harness)

There is no unit-test suite. Verify config edits by loading Vim and checking for
errors:

```bash
# Fast syntax/load check — should print nothing and exit cleanly (exit 0)
vim -u ~/.vim/vimrc -es -c 'qa!'

# Fuller check: source the config and surface any errors to stdout
vim -es -c 'source ~/.vim/vimrc' -c 'messages' -c 'qa!'
```

Any error output (e.g. `E492`, `E117`, script errors) means the change is broken —
fix before finishing. A clean exit with no messages is the pass condition.

Environment-gated blocks (`$MACRC`, `$SERVERRC`, YouCompleteMe) will only fully
exercise on the matching machine; note in your summary if a change touches a branch
you couldn't execute locally.

## Conventions to follow

- **Leader is `,`** (`let mapleader=","`), set near the top intentionally. Keep it there.
- **Indentation**: 4 spaces, `expandtab` globally. YAML and JS use 2 spaces (see the
  `autocmd FileType` lines). Match the surrounding style of whatever you edit.
- **Guard optional plugin config in `try`/`catch`.** The user wraps plugin setup so a
  missing plugin logs a friendly `echo` instead of erroring on load. Preserve this
  pattern when adding plugin config.
- **Group autocmds in named `augroup`s** (e.g. `BradCustom`, `PythonCustom`,
  `BradMacCustom`, `BradLinuxCustom`). Don't add bare `autocmd`s at top level.
- **Respect environment conditionals.** `$MACRC` gates macOS-only features
  (YouCompleteMe, crontab fix). `$SERVERRC` gates Linux/cscope features. Don't collapse
  or remove these guards.
- **Keep commented-out plugin/config lines.** The many `"Plug '...'` and commented
  blocks are an intentional record of things tried/toggled. Do not "clean them up" or
  delete them unless explicitly asked.
- **Plugins**: managed by vim-plug between `call plug#begin(...)` / `call plug#end()`.
  After adding a `Plug` line, the user runs `:PlugInstall`. Fixers/linters run through
  **ALE** (`g:ale_fixers`, `g:ale_linters`); per-filetype overrides live in `ftplugin/`.

## Guardrails (do NOT)

- **Do not edit or commit** anything under `plugged/`, `view/`, `black/`, or other
  gitignored paths.
- **Do not hand-edit** `autoload/plug.vim` (vendored, upstream-managed).
- **Do not remove** commented-out plugin lines, env-var conditionals, or `try`/`catch`
  guards as "cleanup."
- **Do not delete** `vimrc.OLD` or `vmath.vim` unless the user explicitly asks.
- **Do not commit** without an explicit request from the user.

## First-time setup (for reference)

After cloning to `~/.vim` and aliasing `vimrc` → `~/.vimrc`, run `:PlugInstall` inside
Vim to fetch plugins into `plugged/`.
